# 数据清洗边界案例参考

## 日期格式家族（按出现频率排序）

| 输入 | 判定 | 处理 |
|---|---|---|
| `2026/09/11` | 常见斜杠格式 | → `2026-09-11` |
| `11-09-2026` | 歧义（日-月-年 还是 月-日-年？） | 报告，不猜 |
| `20260911` | 紧凑格式 | → `2026-09-11` |
| `2026-13-01` | 非法月份 | 移入 .report.md 遗留问题 |

## 数值列的陷阱

- 千分位逗号：`1,234.5` → `1234.5`（先去逗号再转 float）
- 货币符号：`¥99` / `$99` 混排 → 报告币种冲突，不要擅自换汇
- 负库存：`quantity = -3` 可能是退货冲正——报告，不清零

## 缺失值的三种"假缺失"

1. 空字符串 `""` ≠ NULL（分类列按未知处理，数值列才算缺失）
2. 占位符：`N/A`、`-`、`null` 字符串——先统一映射为 NULL 再统计
3. 逻辑缺失：`refund_time` 在 `order_status != refunded` 时为空——这是
   业务正常的，不算缺失，别填中位数
