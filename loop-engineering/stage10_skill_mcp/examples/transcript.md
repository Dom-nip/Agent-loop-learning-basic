## token 账本对比（本 stage 的核心论据）

| 方案 | 常驻 token | 本会话实际消耗 |
|---|---|---|
| 全量塞两个技能 | ~4200 | 4200（每轮都带） |
| 三层披露（本 stage） | ~110（元数据） | 110 + 正文 620 + 参考 540 = **1270** |

技能库只有 2 个时差距 3 倍；真实工程 30+ 个技能时是 100 倍起步——
且全量塞法还有知识干扰（写周报时清洗规则在场）这个无价代价。

## 这段记录里值得回看的三个瞬间

1. **先读指南再动笔**：模型在收到"写周报"后第一反应是 load_skill——
   元数据 description 的"何时加载"提示起了决定作用。
2. **第三层被主动深读**：read_skill_ref 的触发说明正文里的指路
   （"更详细的写作范例见参考文件"）有效——三层链条完整。
3. **MCP 无感桥接**：模型像用本地工具一样用 mcp_word_count——
   协议层对模型不可见，这正是"基础设施"的定义。
