# stage03 · 上下文工程 —— 记账、截断、分区、压缩

> 第一幕 · 可运行（3/3）。工具协议稳定之后，真正的胜负手浮出水面：**上下文
> （context）管理**。同一个 agent，上下文管理的质量直接决定其表现的上限与下限。

## 1. 本阶段目标

**为上下文建立计量与调控机制**：token 记账（知道消耗在哪里）、工具结果截断
（源头截断）、三分区管理（宪法/文档/历史）、阈值触发的历史压缩（compaction）。
这四件事是第 10-12 章理论的最小工程实现。

## 3. 原理与设计决策

**为什么上下文是胜负手？** 上下文窗口是注意力预算，不是内存：塞得越满，模型对
每一段的注意力越稀薄（lost in the middle），早期指令越容易被"遗忘"。
解法不是换大窗口，而是持续管理：**进得少（截断）、放得对（分区）、定期清
（压缩）**。

**本 stage 的四个机制（都在 `context.py`）：**

1. **token 记账**（`tokens.py` + `ledger()`）：零依赖启发式估算
   （CJK 字符 ×1 + 其他 ×0.25）。目标不是精确值，而是数量级正确的计量。
   真实工程换 tiktoken，其余代码不变。
2. **工具结果截断**（`truncate_tool_result`）：单条结果超过 `TOOL_RESULT_LIMIT`
   字符就头尾各留一段、中间打省略标记。截断发生在"结果进历史之前"——
   污染不进账本，而不是进了账本再清理。
3. **三分区**：
   - 【宪法区】system prompt——永不改动（append-only 原则：改历史 = 摧毁
     prompt cache + 行为漂移）；
   - 【文档区】压缩摘要与注入资料——**时变内容晚注入**的承接区；
   - 【历史区】近期对话——append-only，直到被压缩。
   发给 API 时按 宪法→文档→历史 顺序拼装，顺序稳定是 prompt cache 命中率的
   前提。
4. **阈值压缩**（`maybe_compact`）：历史区超过 6000 token（可调），把老消息
   用 LLM 压成结构化摘要并入文档区。切分点必须是 user 消息——否则会把
   tool 消息和它引用的 assistant tool_calls 拆开，API 将直接返回 400 错误。

## 5. 观察点

- **截断的代价**：big.log 被截断后，模型是声明"内容不全"，还是主动改用
  `run_python` 统计？较优的行为是后者——截断不是信息丢失，而是对模型
  行为方式的引导。
- **压缩质量**：`/compact` 后立即询问"我们之前聊了什么"，观察摘要保留了
  什么、丢失了什么。摘要是有损压缩——丢失的部分要能从 workspace 文件里
  找回。
- **账本曲线**：每完成一个任务查看一次 `/context`，观察历史区的锯齿形曲线
  （增长 → 压缩 → 增长）——它反映了注意力预算的周期性变化。
- **cache 视角**：宪法区永远不变、文档区只增不改、历史区只追加——三个分区
  共同保证 prompt 前缀稳定，这是 KV cache 命中率的全部前提。

## 6. 设计权衡

| 优势 | 代价 |
|---|---|
| 截断让单条污染上限固定，成本可预算 | 截断可能截掉关键信息（需配合分段读取工具） |
| 压缩让会话可以无限继续 | 摘要有损：细节丢失可能引发"记忆幻觉" |
| 分区保住 cache 命中率，长会话成本骤降 | 记账是估算值（±30%），决策阈值要留余量 |
| 全部机制本地可见、可调参对照 | 压缩本身要花一次 LLM 调用（延迟 + 成本） |

## 7. 同期竞争方案的淘汰原因

- **长窗口全量注入路线**（"窗口够大就赢了"）：2024 年的主流论调。被第 10 章 Context
  Rot 实验证伪——窗口再大，注意力依旧稀薄；且按 token 计费时，全量注入
  意味着每轮都为最长上下文付费。
- **每次全量重建上下文**：把"当前相关的一切"每轮重新拼一遍。灵活性最高，
  但前缀每轮都变，KV cache 命中率归零——成本上升可达 10 倍量级。
  分区 + append-only 正是为了保住前缀稳定。
- **滑动窗口硬截断**（丢最老的 N 条）：零成本实现，但"最老的"往往是最重要的
  （任务目标、初始约束）。LLM 摘要压缩成本略高，但把"压缩"变成了"有损但
  保留要点"——以一次调用的代价换取关键信息不丢。

## 8. 与下一个 stage 的衔接

压缩把上下文控制在了窗口内，但**会话一结束，一切归零**——摘要只存在于
当前进程。stage04 将"记忆"外置到文件系统：MEMORY.md、会话摘要落盘、新会话
按需读回——文档区从"进程内的一个 list"升级为"磁盘上的确定性路径"。
